# ADR 0006: 程序演示必须与主站隔离

- Status: Accepted
- Date: 2026-07-17
- Decision Owners: 项目所有者

## Context

“做点啥呢”需要展示本人程序示例。演示可能有独立 CSS、脚本、存储和错误，不能影响主站。

## Decision

演示按风险采用按需加载独立组件、sandbox iframe、外部新标签或视频/截图。不把全部演示打入首页；只有存在站内交互演示时才建立 DemoRegistry。

### 2026-08-06 Clarification：真实外部程序优先

M7 当前优先接入已经独立上线的真实程序。具有真实网址的程序由 Program 详情页说明并通过外部新标签页打开；具有微信小程序或演示媒体的程序，可以在同一详情页组合显示二维码、视频、GIF 或截图。

这一方向仍满足“与主站隔离”的核心决策：需要后端的程序继续由自己的服务器运行，纯前端程序继续由独立静态托管运行，主站不代理其 API、不持有其服务端状态，也不把外部程序源码打进首页。

`Project_Demos`、DemoRegistry、站内静态组件与 sandbox iframe 改为未来按需能力，不再作为当前 M7 的强制前置或退出条件。只有出现必须在站内运行的交互演示时，才恢复相应注册表和沙箱实现；届时本 ADR 的权限、按需加载和错误隔离要求继续有效。

外部链接必须使用真实 HTTPS 地址与 `noopener noreferrer`。外部媒体只在详情页按需加载；媒体或外站失败不得破坏主站静态详情正文。任何真实程序的后端、登录、数据库、支付或实时能力都必须如实描述，不能由主站假实现。

## Alternatives

所有演示直接嵌入主组件；只提供截图；自建统一后端。

## Consequences

隔离更安全，加载更轻；外部程序路线只需真实入口、媒体失败边界和隐私说明。未来恢复站内交互演示时，才额外需要注册表、iframe 权限和沙箱错误边界。

## Verification

当前外部路线验证：外站或媒体失败不导致主站白屏；主站生产输出不增加服务端运行时；详情正文和主要信息仍可静态访问；外链具有安全属性且媒体未进入首页包。

未来 iframe 路线验证：iframe 不能任意控制顶层页面，脚本、存储和样式不污染主站。
