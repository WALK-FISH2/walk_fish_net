# M6.3 普通内容页纵向滚动修复规格

状态：已完成实现与正式验收  
确认日期：2026-08-06
完成日期：2026-08-06

## 1. 问题

当前 `/articles/`、`/articles/<slug>/`、`/programs/`、`/programs/<slug>/` 和 `/about/` 共用普通页面外壳。`BaseLayout.astro` 把 `page-shell` class 放在 `body` 上，而 `global.css` 中 `.page-shell { overflow: hidden; }` 同时关闭了横向和纵向溢出，因此内容超过一屏时无法继续向下阅读。

移动导航在展开期间临时锁定 body 滚动是另一条独立逻辑；它必须在菜单关闭后恢复，但不是本问题中普通页面永久不可滚动的主要原因。

## 2. 目标

- 普通内容页使用浏览器原生纵向滚动；
- 继续阻止页面级横向溢出；
- 列表页、详情页和关于页均可到达最后一项内容与页脚；
- 不改变沉浸式首页的 ScrollTrigger、五段进度、动效模式、Canvas 或场景高度。

## 3. 路由范围

```text
/articles/
/articles/<slug>/
/programs/
/programs/<slug>/
/about/
/404.html
```

后续新增的普通 `page-shell` 路由也必须默认允许纵向滚动。

## 4. 交互要求

1. `page-shell` 只约束横向溢出，不得把 `overflow-y` 设为 `hidden`；
2. 鼠标滚轮、触控板、触摸拖动、PageDown/PageUp、Home/End 与浏览器滚动条均有效；
3. 列表筛选、详情目录和站内链接不创建第二个页面级滚动容器；
4. 移动导航只在打开期间临时锁定文档滚动；关闭按钮、链接选择、Escape、视口切换和组件卸载都必须恢复原状态；
5. 返回列表、浏览器前进/后退和直接刷新详情页后仍可滚动；
6. 允许内容自然增长，不以固定高度或裁切隐藏超出部分；
7. `scrollWidth <= clientWidth`，不得以恢复纵向滚动为代价产生横向滚动条。

## 5. 非目标

- 不修改首页滚动叙事或动效模式；
- 不改文章、Program 内容字段或路由；
- 不引入滚动平滑库、整页吸附、虚拟滚动或嵌套主滚动容器；
- 不改导航视觉、正文排版和 Programs 卡片版式。

## 6. 验收矩阵

桌面端和 `375x812` 分别验证：

- 上述列表页、详情页和关于页从顶部滚动到底部，再返回顶部；
- 鼠标/触摸、PageDown/PageUp、Home/End 均可继续推进；
- 可到达页脚、详情末段、上一篇/下一篇或最后一张列表卡片；
- 移动菜单打开时页面被锁定，关闭、Escape 和选择链接后恢复；
- 刷新详情页、前进/后退后滚动正常；
- 页面级横向溢出为 0；
- Tab 焦点可到达屏幕外的后续交互项，浏览器会正常滚动到焦点；
- 控制台没有未处理错误。

自动化至少覆盖 `.page-shell` 不再关闭纵向溢出，以及移动导航锁定/恢复行为。完成 Astro Check、ESLint、测试、生产构建与静态路由验证后，M6.3 才能关闭。

## 7. 实施结论

- `.page-shell` 现在使用 `overflow-x: hidden; overflow-y: auto`，普通页面继续由浏览器 document/body 承担唯一主滚动；
- 移动导航保存打开前的 inline overflow，并在关闭、Escape、链接选择、桌面断点和 `pagehide` 时恢复；
- 列表页移动端 Hero 装饰限制在自身裁切边界内，桌面分隔线不再用 `100vw` 扩张页面宽度；
- 1280×720 和 375×812 的六类路由均可到达页脚并返回顶部，最终页面级横向溢出为 0；
- Program 详情直接刷新、站内菜单导航、浏览器前进后退和 `?motion=reduce` 均保持可滚动；
- 首页完整动画仍可完成 land → space → land 往返，故事高度、Canvas 数和动效模式未改变；
- Astro Check、ESLint、18 项测试、生产构建与静态路由验证全部通过。详细数值见 `tasks.md` 和 `docs/engineering/adjustment_record.md` 第 12 节。
