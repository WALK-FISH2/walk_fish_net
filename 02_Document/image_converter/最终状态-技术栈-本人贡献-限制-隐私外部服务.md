- **Server**：可通过 FFmpeg 逐帧处理小程序上传的视频，输出保持原始比例、黑色背景的 H.264 MP4，并尽可能保留音频。

**当前限制**

- Web 导出会在内存中保存完整结果，超长或高分辨率视频可能占用较多内存。
- VP9/WebM、异常音轨转码和无声降级尚未完成完整真机验证。
- WebCodecs 需要较新的 Chrome/Edge，并要求 localhost 或 HTTPS 安全上下文。
- 小程序视频处理是同步请求，没有实时进度、任务队列、取消和重试。
- Server 默认约 12 FPS，逐帧 CPU 渲染速度仍有优化空间。
- Server 接收 `glow` 参数，但成片渲染尚未实际使用。
- 三端分别维护部分字符集和渲染公式，存在效果漂移风险。
- 小程序 API 地址仍是源码配置，模拟器和真机需要切换地址。
- iOS 真机、小程序公网部署和长期运行尚未验证。
- Server 生成文件没有自动过期和清理机制。

**隐私与外部服务**

- **Web 图片和视频完全在浏览器本地处理**，不会上传到项目 Server。
- **小程序图片在设备本地处理**；视频会上传到配置的 Node Server。
- Server 会将原视频、临时文件和处理结果写入本机 `storage` 目录，目前不会自动删除。
- 当前项目**没有接入第三方云端 AI、分析统计、广告、账号系统或对象存储服务**。
- Mediabunny、FFmpeg 和 FFprobe 均是本地运行的软件组件，不会自行把媒体发送到外部服务。
- 微信小程序本身受微信平台权限和隐私规则约束，保存到相册时需要用户授权。
- 局域网调试使用 HTTP，不具备传输加密；不应直接暴露到公网。
- 当前视频 API 没有鉴权。正式上线前需要增加 HTTPS、访问控制、上传校验、限流、文件自动清理和隐私说明。
